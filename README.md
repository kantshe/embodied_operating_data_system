# 具身智能操作数据管理系统

Embodied Operating Data System

面向机器人操作任务的离线数据管理工具，用于整理采集记录、检查数据质量，并生成可追溯的数据集版本。

> 当前阶段：方向规划。仓库尚无可运行程序，以下功能、技术选型与里程碑均为开发计划，不代表已经实现。

## 开发方向

以“机器人桌面抓取与物体搬运”为首个应用场景，服务于整理实验数据的开发人员和数据管理员。

系统关注一次操作任务产生了哪些数据、数据是否完整、哪些记录可以纳入数据集，以及导出的数据来自哪里。首版采用离线文件导入，不依赖真实机器人在线连接；开发阶段使用明确标记的合成样例验证流程，不将其描述为真实设备采集数据。

首版的完整流程：

**创建项目 → 导入采集批次 → 检查操作记录 → 标记与筛选 → 生成数据集版本 → 导出**

## 要解决的问题

- 采集文件分散在不同目录，任务、设备和操作结果难以对应。
- 视频、状态序列等文件缺失时，缺少统一的检查结果。
- 成功、失败及失败原因没有一致的记录方式，筛选依赖人工翻目录。
- 导出的样本集合缺少固定版本，难以还原某次使用的数据范围。

## 首版范围

| 模块 | 计划能力 | 验收目标 |
| --- | --- | --- |
| 项目与任务 | 管理项目、任务名称、场景和设备标识 | 可以创建项目并查看其任务及操作记录 |
| 离线导入 | 按约定的 JSON 清单导入元数据及关联文件 | 返回逐条导入结果；重复导入不重复创建记录 |
| 记录检索 | 按任务、设备、采集时间和操作结果筛选 | 列表与详情展示一致，筛选条件可组合 |
| 记录查看 | 展示元数据、关联视频和状态数据摘要 | 能定位原始文件；缺失文件有明确提示 |
| 质量检查 | 检查必要字段、文件存在性、时间范围及序列时间戳 | 每项问题可追溯到具体记录和检查项 |
| 人工标记 | 标记成功、失败、待确认及失败原因 | 保留修改前后值和修改时间 |
| 数据集版本 | 将选定记录及其元数据固定为一个版本 | 后续修改记录不改变已生成版本 |
| 导出 | 导出版本清单、质量报告和关联数据文件 | 清单包含文件校验值，可检查导出完整性 |

首版暂不包含：

- 机器人实时控制、遥操作及设备驱动。
- 在线流式采集和多设备实时同步。
- 模型训练、推理服务及自动生成操作策略。
- 视频逐帧标注、三维场景重建等复杂编辑工具。
- 多租户、复杂权限系统及大规模分布式存储。

## 数据组织

以一次完整操作记录（Episode）为核心。一个项目包含多个任务，一个任务可以对应多次操作记录。

| 对象 | 含义 | 计划记录的信息 |
| --- | --- | --- |
| Project | 数据管理项目 | 名称、描述、创建时间 |
| Task | 操作任务定义 | 任务名称、操作目标、场景 |
| ImportBatch | 一次导入批次 | 来源、导入时间、成功与失败明细 |
| Episode | 一次操作记录 | 来源标识、设备标识、起止时间、操作结果、数据来源类型 |
| Asset | 关联数据文件 | 相对路径、文件类型、大小、校验值 |
| QualityReport | 质量检查结果 | 检查规则版本、问题明细、检查时间 |
| AnnotationRevision | 人工标记修改记录 | 修改前后值、修改时间 |
| DatasetVersion | 固定的数据集版本 | 样本集合、元数据快照、文件校验值、生成时间 |

导入格式将在实现导入模块前单独定义并版本化，首版拟支持：

- JSON：批次清单和操作记录元数据。
- MP4：关联的操作视频。
- CSV：按时间排列的状态或动作序列。

具体字段、时间单位、必填项及文件路径规则以届时提交的格式说明和校验逻辑为准。首版不承诺兼容外部数据集格式。

原始导入文件与人工标记分开保存，不通过修改原始数据表达审核结果。数据集版本生成时固定所选数据及其校验值，导出时发现源文件变化应明确报错，不静默替换。

## 技术方案

以下为首版拟采用的方案，实际依赖及版本以实现时提交的配置文件和锁文件为准。

| 层次 | 计划选型 | 用途 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 列表、详情、导入结果和数据集管理界面 |
| 后端 | Python + FastAPI | 元数据管理、文件导入、质量检查和导出接口 |
| 数据库 | SQLite | 单机环境的结构化元数据存储 |
| 文件存储 | 本地文件系统 | 保存导入文件及导出产物 |
| Python 环境 | uv | 环境创建、依赖管理和锁定 |
| 验证 | pytest 与必要的浏览器流程检查 | 校验导入、版本固定、导出及关键界面流程 |

首版以本机单用户运行为目标。先完成离线数据闭环，再根据实际数据规模决定是否引入其他数据库、对象存储或后台任务服务。

## 维护方式

- 每次提交对应真实完成的文档、功能、修复或验证工作，提交说明描述实际变更。
- 根据改动规模使用分支和 Pull Request；小型文档调整不强制创建合并流程。
- 实现功能时同步更新里程碑状态，不把计划能力提前写成已完成。
- 功能验收记录注明验证条件和结果；未验证内容明确列出。
- 已有记录的提交日期保持真实，不补造历史开发活动。
