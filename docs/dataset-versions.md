# 数据集版本

在项目的“数据集版本”页创建版本，填写名称并勾选记录。选择跨页保留，支持本页全选和清空；创建失败保留名称和选择。列表、可选记录每页显示 20 条，提供加载、空状态和失败重试。

版本详情地址为 `#project=<项目 ID>&view=versions&version=<版本 ID>`，可直接打开或刷新。返回列表保留本次页面的页码。展开记录可查看当时的结果、失败原因、任务、设备、起止时间、来源、文件大小、SHA-256 和最近一次检查报告。

## 接口

| 接口 | 行为 |
| --- | --- |
| `POST /api/projects/{project_id}/versions` | 创建版本，成功返回 `201` 和完整快照 |
| `GET /api/projects/{project_id}/versions` | 返回版本摘要列表，按创建时间和写入顺序倒序 |
| `GET /api/projects/{project_id}/versions/{version_id}` | 返回版本详情和完整快照 |

创建示例：

```json
{
  "name": "桌面抓取基线",
  "episode_ids": ["记录 UUID 1", "记录 UUID 2"]
}
```

名称去除首尾空白，长度为 1–200 字符；一次选择 1–500 条记录，拒绝重复 ID、空 ID 和未知字段，格式错误返回 `422`。所有记录必须属于当前项目，任意一个不存在或归属不符返回 `404`，不保存部分版本。

列表接受 `limit`（1–100，默认 20）与 `offset`（非负整数）。摘要含 `id`、`project_id`、`name`、`created_at`、`episode_count`，详情增加 `snapshot`。版本不属于当前项目或不存在时返回 `404`。同名版本允许创建，以 ID 区分；没有修改或删除版本的接口。

## 快照规则

`snapshot.schema_version` 为 `1`，包含项目元数据与按请求顺序排列的 `episodes`。每条记录保存完整元数据，包括人工标注及其版本号，并附带：

- `task`：创建版本时的任务元数据。
- `assets`：关联文件的 ID、路径、类型、实际大小和 SHA-256。
- `quality_report`：当时最近一份检查报告，含规则版本、时间和问题；未检查时为 `null`。

创建时逐个读取文件并计算 SHA-256，不依赖 CSV 预览。文件路径限制在配置的存储目录，拒绝符号链接和非普通文件。没有关联文件、文件无法读取，或实际大小、校验值与已登记值不一致时返回 `409`。读取期间检测到文件变化也返回 `409`。历史资产没有大小或校验值时，在版本内补存实际值，不修改原资产记录。

元数据读取和版本写入在同一 SQLite 事务内执行。创建失败不会留下版本；记录数较多或文件较大时，计算校验值会占用时间，并暂时阻塞其他数据库写入。

版本保存元数据和文件校验值，不复制文件内容。创建后的任务、标注、检查报告或文件变化不会改写已有快照。文件系统不具备跨文件原子快照能力，因此后续导出仍须对照版本中的大小和 SHA-256 验证文件；导出与下载属于第 11 阶段。

创建版本不要求最新检查通过，也不会自动运行质量检查。报告仅代表其检查时刻，不能作为版本创建时全部数据合格的证明；未检查、检查失败或未完成的报告均原样保留，便于复核。
